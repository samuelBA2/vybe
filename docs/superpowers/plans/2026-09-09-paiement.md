# Paiement réel (fournisseur à décider) — Plan d'implémentation

> **Pour les workers agentiques :** SOUS-SKILL REQUISE — utiliser superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Étapes en cases à cocher (`- [ ]`).

**Goal :** Remplacer le stub `OrderService.createOrder` par un vrai flux de paiement Mobile Money, **fournisseur non arrêté** : `Order` `PENDING` → paiement → webhook re-vérifié serveur → `PAID` qui génère les billets **et** crédite le ledger (85 % organisateur / 15 % plateforme). + reaper + comptabilité organisateur (lecture seule V1). Payout = **Lot 2**.

**Architecture :** Module `src/payments/` avec interface `PaymentProvider` couvrant les deux formes d'intégration (checkout hébergé **ou** push Mobile Money). Ledger signé (`LedgerEntry`) écrit dans la transaction du `PAID`. États `PaymentStatus.EXPIRED`/`REVIEW`, enum `Currency`. Endpoints : `POST /order` (réécrit), `POST /payments/webhook`, `GET /order/:paymentRef/status`, `GET /me/earnings`(+history). Reaper `payments.cleanup.ts`. Spec : `docs/superpowers/specs/2026-09-09-paiement-design.md`.

**Tech Stack :** NestJS, Prisma (Postgres/Neon), Jest, `fetch` natif (aucune nouvelle dépendance).
